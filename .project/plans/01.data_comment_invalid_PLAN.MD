# Correção da Exibição de Datas Inválidas nos Comentários

## Visão Geral

Este plano aborda um problema onde a data de criação dos comentários está sendo exibida como inválida no frontend quando retornada via endpoint de tarefas, mas não quando retornada via endpoint direto de comentários. O problema está relacionado à forma como as datas são serializadas quando obtidas através de consultas SQL raw.

## Análise do Estado Atual

### Como Funciona Atualmente:

1. **Endpoint `/comments` (Funciona corretamente)**:
   - Usa TypeORM com relações
   - Retorna objetos Date corretamente serializados
   - Exemplo: `"created_at": "2025-09-19T21:19:25.103Z"`

2. **Endpoint `/tasks/:id` (Problema)**:
   - Usa SQL raw para carregar comentários e seus likes
   - Retorna strings PostgreSQL diretamente
   - Exemplo: `"createdAt": "2025-09-19T18:19:28.780531-03:00"`

### Descobertas Chave:

- **Local da Consulta Problemática**: `backend/src/modules/tasks/services/task.service.ts` linhas 75-101
- **Problema Específico**: Na consulta SQL raw, o campo `created_at` dos likes é retornado diretamente do PostgreSQL como string no formato `2025-09-19T18:19:28.780531-03:00`, mas quando serializado pelo interceptor, não é convertido para Date object JavaScript.
- **Configuração Correta nas Entidades**: As entidades `Comment` e `CommentLike` estão corretamente configuradas com `@CreateDateColumn({ name: 'created_at', type: 'timestamp with time zone' })` e tipo `Date`.

## O Que NÃO Estamos Fazendo

- Alterar a estrutura das entidades
- Modificar o comportamento do TypeORM
- Alterar o interceptor de transformação
- Mudar a forma como os endpoints de comentários funcionam

## Abordagem de Implementação

Corrigir a consulta SQL raw no `task.service.ts` para garantir que os campos de data sejam retornados em um formato que possa ser corretamente serializado como objetos Date pelo Nest.js.

## Fase 1: Corrigir a Consulta SQL Raw

### Visão Geral

Modificar a consulta SQL raw no método `findOne` do `TaskService` para converter explicitamente os campos de data para o formato ISO adequado.

### Alterações Necessárias:

#### 1. Atualizar a Consulta SQL
**Arquivo**: `backend/src/modules/tasks/services/task.service.ts`
**Linhas**: 95-99

```typescript

'createdAt', cl.created_at

// Para:
'createdAt', cl.created_at::timestamp with time zone AT TIME ZONE 'UTC'
```

## Considerações de Performance

A correção adiciona uma conversão de timezone na consulta SQL, mas:
- O impacto no desempenho é mínimo
- A consulta já é complexa e otimizada para carregar comentários aninhados
- Não há impacto no desempenho do frontend
- A consistência dos dados é mais importante que a micro-otimização

## Notas de Migração

Esta é uma mudança compatível com versões anteriores que apenas corrige a exibição das datas:
- O código existente continua funcionando
- A correção não requer migração de dados
- Não há impacto em outras funcionalidades
- Os usuários não precisam fazer nenhuma ação adicional
